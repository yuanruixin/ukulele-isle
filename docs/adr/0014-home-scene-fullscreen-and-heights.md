# ADR 0014: 首页场景占满全屏，并靠「分层落脚面」做出高低

## 状态

已接受 (2026-09-17)

## 背景

按 ADR 0013，首页是一幕「猫咖」：一层墙 + 一层木台面，四只猫站在台面上，
`left`（不等距）/ `bottom`（前后排）/ `height`（纵深）/ `z-index` 全部不等。

用户看完给的反馈是 **"现在还是在一个水平面上，我是说参考猫咖中的一些猫架，然后让高低都有"**。
诊断下来完全正确，而且指出了一个 ADR 0013 漏掉的变量：

| 变量 | ADR 0013 的状态 |
|---|---|
| 宽度 / 间距 / 尺寸 | 已破（`left` / `height` 各不相等）|
| **高度** | ❌ **没破** —— 四只猫的 `bottom` 虽然不同（8% / 12% / 15% / 18%），但那只是**同一条台面线上的前后排**，脚底下踩的是同一个平面 |

也就是说：破的是一个平面**内**的整齐，没破的是"只有一个平面"这件事本身。
**一个场景里只有一层台面，猫除了并排别无选择。**

用户同时给了三条具体改动：全屏（不是画面的一部分）、PC 加物件 / 手机减件、
照参考图补凳子之类的物件并把配色换成暖木色；两条 bug：第 4 只猫身体透明（已单独修）、
唱片机的方向不对（已单独修）。

四个分叉由用户当场拍板：**不要站名**、**窄屏换一套竖向构图**（不是缩放、不是裁切）、
**4 只猫落在 4 层**、**换成暖木色**。

## 决策

**1. 首页只剩这一幕，并且占满导航栏以下整屏。**

站名与副标题从首页撤掉（导航栏左上角一直挂着，不需要在首页再说一遍），
`.home-stage` 的宽高由页面留白改成**整屏**：

```css
.home-stage { height: calc(100dvh - var(--nav-h)); min-height: 360px; }
```

★ **不去套 flex 外壳**（`flex:1` + 子项 `height:100%`）：那条路要依赖"百分比高度能否
穿过 flex 项解析"，而且 `.app-main` 一旦变成 flex 容器，别的页面里那些
`mx-auto max-w-5xl` 的 `<main>` 会因为交叉轴 auto margin 而改变尺寸语义。
一个数写死最稳。

**2. 造出四种**互不相同**的落脚面，猫按"高度"而不是"前后"分布。**

```
猫架（壁挂搁板） → 吧台台面 → 高脚凳 → 木地板
     curl            sleep      listen     sing
```

这四层是**结构**（猫架、吧台、凳子、地板各自独立存在），不是把猫抬高一点点。
新增的猫架 / 窗 / 咖啡机 / 罐架 / 高脚凳 / 圆木桌 / 坐垫都在
`src/components/scene/SceneProps.tsx`，位置尺寸仍全在 `globals.css`。

**3. ★ 落脚面抽成变量，猫与道具引用同一条线。**

```css
--line-shelf: 76%;  --line-seat: 34%;  --line-cushion: 6%;
--line-deck: var(--hs-deck);   /* 吧台台面 = --hs-deck */
```

- 道具：`bottom: calc(var(--line-seat) - var(--h-stool) * 0.879)`（座面中心在造型里
  离底 102/116）
- 猫：`bottom: calc(var(--line-seat) - var(--cat-listen-h) * var(--pad-listen))`

一件事只有一个来源，改构图只改这一组数；实测四只猫的造型底边与落脚线**误差 < 0.01%**。

**4. 承重的道具按「高度」给尺寸，其余按宽度。**

猫架 / 高脚凳 / 坐垫 / 圆木桌的关键线在造型中段，**按宽度给尺寸的话屏一宽它们就变高，
落脚线会漂**。所以这几件 `height: <场景高的 %>`、里面的 `svg { width:auto; height:100% }`；
灯 / 杯 / 吊牌这些不承重的仍按宽度给（`clamp()` 兜住两端）。

**5. 横屏与竖屏是两套构图，切换看**画面比例**而不是屏宽。**

```css
@media (min-aspect-ratio: 5/4) { …整组换掉落脚面、尺寸、站位… }
```

判据是比例：横屏才放得下"一排四层"，竖屏只能用"上下四层"。竖屏还额外**收件**
（藏掉咖啡机、圆木桌、第二只凳子、第二盏灯、第二盆挂植）——这正是用户说的"手机端收束一下"。

## 后果

### 三个坑（都是**静默**的，一个错都不报）

**① 猫的造型在取景框里不贴底，而且每个姿态留的白边不一样。**

引擎的 `frame:'thumb'` 四周留边，实测（占框高的比例，用 `svg .norm` 的静态
bbox × transform 量）：

| 姿态 | listen | sing | curl | sleep |
|---|---|---|---|---|
| 离框底 | 0.236 | 0.227 | 0.236 | **0.023** |

所以 `bottom` 必须写 `落脚面 − 高度 × 这个比例`。
睡姿几乎不留边、看着一直是对的；**另外三只会整只飘在半空**。
第一版把符号写成了加号，四只猫一起飞到天花板；把比例写成带 `%` 的变量，
`calc(13% * 23.6%)` 是 `% × %`、非法 ⇒ 整条 `bottom` 静默失效回落到 `auto`，**又是**一起飞。
⇒ 这四个比例必须是**无单位数**，且**换描摹稿 / 换 frame 时要重新量**。

**② 道具造型的 viewBox 底边往往不是"坐地的那条线"。**

`<svg viewBox="0 0 100 122">` 的凳子腿只画到 y=116，直接拿元素底边当落脚线就差 6/122。
全部道具的 viewBox 下缘都收边到"真正落地的那一行"（凳 116、垫 64、桌 138、盆 62……），
对照表写在 `SceneProps.tsx` 末尾。**改了造型的 viewBox 高度，比例就要跟着重算。**

**③ `header` 的 `border-bottom: 0.5px` 让导航栏实际高 57px。**

整屏高度按 `--nav-h: 56px`（= `h-14`）算，差这 1px 就冒出纵向滚动条。
解法是把那条线从**布局**里挪出去、改用 `box-shadow: inset 0 -0.5px 0` 画。
⇒ 凡是拿"导航栏高度"去减 `100dvh` 的地方（首页 / 虚拟尤克里里的移动端一屏）
都吃这一条，别再靠 JS 去量 header。

### 其它

- ★ **配色整套换成暖木色**（奶油墙 + 木吧台 + 鼠尾草绿护墙板 + 暖木地板 + 暖黄吊灯），
  取自用户给的参考图；深色那套 = "打烊后的店，只留一盏灯"，并给灯加了
  一层径向渐变**光池** —— 只把灯泡点亮是不够的，屋子还是一块黑。
- 参考图里的 **MENU 标价牌没有照搬**（用户明确要求去掉咖啡价格那类物件）。
- 首页的 `--scene-ratio` / `--scene-ratio-sm` 两个令牌**删掉**：场景不再由比例定形状。
- 破整齐的判据从"位置全不等"升级成"**脚底下的那条线全不等**"：
  竖屏 ≈ 73.6 / 45.7 / 29.3 / 0.1%，横屏 ≈ 70.9 / 49.6 / 21.0 / −0.3%
  （两组都按 `curl / sleep / listen / sing` 排）。

## 验证（2026-09-17）

- `tsc -b` 干净、`pnpm build` 通过。
- **满屏**：1440×820 下 `header` 高 56、场景 56→820、`scrollHeight === clientHeight`
  （**无纵向滚动条**）。
- **对位**：脚本量「造型底边在场景里的高度」与 `--line-*` 相减，四只猫
  `listen −0.01% / sing +0.01% / curl −0.01% / sleep −0.01%`；猫架搁板上沿与凳子座面
  与变量值完全一致。
- **四组合视觉验收**：浅/深 × 横屏(1440×820、2560×1080) / 竖屏(390×844)，
  另加一个极矮窗口(1920×640)确认 `max-height: 720px` 那一档媒体查询生效。
  深浅两套都看过（换色类改动必须两边都看）。
- **吊牌可交互**：点击 `.scene-sign-1` 实测跳到 `#/songs`；
  `elementFromPoint` 落在牌子上返回 `scene-sign-label`（没有被猫层盖住）。
- `docs/images/home.png` 与 `home-dark.png` 已按 1440×900 重拍。

> 与 ADR 0013 的关系：0013 破的是"平面内的整齐"，这一条破的是"只有一个平面"。
> 0013 的结论（位置全放 CSS、吊牌是真的链接、唱片机与 bpm 同源）**继续有效**。
