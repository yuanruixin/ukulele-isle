# ADR 0010: 把音色与效果链推广到曲谱与和弦库（全站三个播放器统一）

## 状态

已接受 (2026-09-17)

## 背景

ADR 0009 只修了**虚拟尤克里里**一个播放器，并在「后果」里明确写下：

> **只挂在虚拟尤克里里这一个播放器实例上**，不做全局改造。和弦库与曲谱页各有自己的播放器实例，
> 目前**没有**这条效果链（同样的「干」问题在那里依然存在）。

用户随后问「现有曲谱工具会进行润色吗」。去核对代码，发现情况比预想更严重——

| 播放器 | `\instrument` | 效果链 |
| --- | --- | --- |
| 虚拟尤克里里 | ✅ 写 `24`（0009 已修） | ✅ 有 |
| 曲谱（`/song/:id`） | ❌ **没写** → 默认 **25 钢弦吉他** | ❌ 无 |
| 和弦库（`/tools/chords`） | ❌ **没写**（`chordTex()` 不生成） | ❌ 无 |

`songs/aoi-shiori/score.tex`、`songs/qingtian-intro/score.tex` 两份谱面都只有
`\title…\artist…\tempo…\tuning…`，**都没有 `\instrument`**。也就是说 0009 认定的
「尖」的头号根因（钢弦吉他音色播尼龙弦乐器）在这两处**一直存在**，只是当时没顺手一起修。
再加上没有效果链，曲谱与和弦库实际比虚拟尤克里里**更尖、更干**。

## 决策

1. **音色收敛为一个站点级常量**：新增 `SITE_INSTRUMENT`（默认 **24 = 尼龙吉他**），
   `player` / `chords` / `uke` 三个配置块的 `instrument` 都读它——换味道改一个数，
   同时保留各播放器单独覆盖的能力。
2. **曲谱的 `\instrument` 不落盘，加载时补**：新增 `src/lib/songTex.ts` 的
   `withDefaultInstrument()`，由 `ScoreView` 在 `api.tex()` 之前调用；
   **谱面自己写了 `\instrument` 就以作者为准**（原样放行）。
3. **和弦库的 `\instrument` 直接写进生成器**：`chordTex()` 的入参加 `instrument`，
   谱面本来就是它现生成的，不需要第二套机制。
4. **效果链推广到三个播放器**：新增 ★ `player.fx` 与 ★ `chords.fx`（结构与 `uke.fx` 一致），
   并把接线从 `useUkulelePlayer` 里抽成通用 hook **`src/hooks/useSynthFx.ts`**，
   三个播放器共用同一份实现（`useUkulelePlayer` 一并改用它，行为不变）。
5. **参数故意不完全一样**：低通的**截止点与级数全站同一档**（3400Hz 两级，音色才统一）；
   **混响湿度按内容形态定**——曲谱 `0.15`、和弦库 `0.25`、虚拟尤克里里 `0.25`。
6. **~~三处都给 A/B 开关~~ →（同日修订）三处都不给开关**：最初按「方便对比」的目的，
   在曲谱页「‹ 所有歌曲」行右侧、和弦库与虚拟尤克里里头部右上角各放了一个「音色润色」开关；
   **用户随后要求「润色改为本地系统中配置，不需要在页面中添加开关」，已全部撤掉**。
   现在**唯一决定有没有效果链的地方就是配置里的 `fx.enabled`**（见文末「修订」）。

## 理由

- **为什么把 `instrument` 抽成常量，而不是三处各写个 24**：这是**一个审美决定**
  （「本站的尤克里里该是什么音色」），不是三个独立决定；同一件事分写三处，改的时候一定会漏一处。
  同时保留各块的 `instrument` 覆盖位，因为单点调音（比如想让和弦库更亮）仍有价值。
- **为什么曲谱不直接改 `score.tex`**：谱面文件必须始终等于「作者写的样子」——
  这正是文件驱动那条约定的全部意义（ADR 0002）。在内存里补一行，既拿到了统一音色，
  又保证用户手改谱面时不会被工具反向污染。
- **为什么混响要分开、低通不分开**：低通决定的是**音色本身**（同一个乐器必须听起来一样），
  必须全站一致；混响决定的是**空间感**，而曲谱是**复音 + 连续播放**、混响会一路累积，
  与「拨一下、等余音」的单次发声根本不是一回事——同一湿度在曲谱上会明显更糊。
- **为什么抽 hook 而不是复制三份接线**：三处要做的事完全一样（① 播放器建好才能拿输出节点，
  得在构造后与 `playerReady` 各试一次；② 卸载时拆线、把被包过的 `play()` 还原）。
  复制三份必然有一份忘改——事实上 `useUkulelePlayer` 已经有一份内联实现，
  这次把它一起换成共用 hook，避免两份实现并存。
- **为什么不做「暂停时掐掉混响尾巴」**：默认让它自然衰减更接近真实演奏。
  真需要的话在 hook 上加一个 `duck()` 即可（**未做**，留给用户决定）。

## 后果

- **全站音色一致**：三个播放器都是 24 尼龙吉他 + 同一档低通（3400Hz 两级）。
  想给全站换味道改 `SITE_INSTRUMENT`；想只给某一个换，改那一块的 `instrument`。
- ⚠️ **不要在 `songs/<id>/score.tex` 里写 `\instrument` 来「修音色」**——那是站点级决定。
  写了会被尊重（`withDefaultInstrument` 不覆盖），但会让这首歌和其它歌不一致。
- 曲谱播放现在会经过效果链，因此**暂停后混响尾巴还会响一小会儿**（长度 = `reverbSeconds`）。已接受。
- 新增两块配置（`player.fx` / `chords.fx`）与一个 hook（`useSynthFx.ts`）；
  **`synthFx.ts` 本身一行没改**——它对内容形态完全无关，这也是「能推广」的前提。
- 打包：主包 231.1 → 232.2 KB（+1.1 KB：hook + 注入函数 + 页面的接线）；撤掉开关后略降。
- **仍然没解决**（与 0009 相同）：单音不叠加、力度写死 95、音色库采样上限 11–32kHz。
  彻底对齐网站（真实采样 + 复音）依旧需要重写发声层。

## 验证（2026-09-17）

`tsc --noEmit` 与 `npm run build` 均通过（主包 231.1 → 232.2 KB）。

**音色层（离线、确定性）**——用 Node + `AlphaTexImporter` 直接解析谱面，不看渲染结果：

- 两首曲谱注入后 `track.playbackInfo.program` 都是 **25 → 24**，
  且**音高序列一字未变**（按 `弦号:品` 逐音比对指纹，10 小节 / 4 小节全长比对通过）。
- 和弦库产物含 `\instrument 24`，位置在 `.` 之后、`\tuning` 之前（构建函数里断言过索引顺序）。
- 谱面自己写了 `\instrument` 时**原样放行**（拿 105 班卓试的，解析出来就是 105）。
- 三个配置块的 `instrument` 与 `SITE_INSTRUMENT` 三者一致。

**效果层（真实浏览器）**——三个播放器都验到「合成器输出被改接到效果链入口」：
`connect AudioWorkletNode -> AudioDestinationNode`（alphaTab 自己接的）
→ 建链（两级低通 → 干声 / 卷积湿声 → 总增益 → destination）
→ `disconnect AudioWorkletNode` → `connect AudioWorkletNode -> 入口`。
（当时链里还有两个闸门，现在没有了；验到的改接顺序不变。）

**声音真的还在流**（挂链没把声音弄哑）——在**总增益**节点上挂 AnalyserNode
（经零增益接 destination，否则该支路不被处理）量时域峰值：曲谱页 **0.43**、
虚拟尤克里里 **0.26**，且 `AudioContext.state === "running"`。

**A/B 开关**（~~已撤销~~，见文末修订）——当时在曲谱页切一下：开关状态翻转，
**恰好两次 `setTargetAtTime`**（直通闸 → 1、效果闸 → 0），**没有任何 connect / disconnect**
⇒ 音频图不重建、不打断正在播放的曲子。开关本身是好用的，只是**用户不要页面上有这个入口**。

**版式**（~~已撤销~~，见文末修订）——曲谱页开关落在「‹ 所有歌曲」那一行右侧；和弦库在头部右上角，
390×844 下与居中标题不碰撞（两张截图确认）。撤掉开关后这几行恢复原样。

**没有单独验的一项**：和弦库「挂链之后仍能出声」没有单独量到——不是代码问题，
而是无头里给它的那次点击没被算作用户激活、`AudioContext` 一直是 `suspended`（量出来全 0）。
它走的是与曲谱页**完全相同**的 hook 与 `synthFx.ts` 代码路径，所以按曲谱页的结论采信。

## 修订（2026-09-17，同日）

用户原话：**「润色改为本地系统中配置，不需要在页面中添加开关」**。

这直接推翻了上面的决策 6。改法：

1. **三个页面**（`SongPage` / `ChordsPage` / `UkulelePage`）删掉「音色润色」开关整块 JSX 与
   `Switch` 的 import；`SongPage` 的 `<nav>` 恢复成只有「‹ 所有歌曲」，另外两页头部去掉
   为绝对定位而加的 `relative`。`UkulelePage` 里那行宽屏提示（原来说「右上角的开关 = 低通 + 混响」）
   一并删掉。
2. **`synthFx.ts` 回到单路**：删掉 `bypass` / `out` 两个闸门、`setEnabled()`、`TOGGLE_RAMP_S`
   与交叉淡化的 `setGain()`；`build()` 里 `master.connect(ctx.destination)` 直接落地。
   `SynthFxOptions.enabled` 的语义从「初值」变成「**唯一的开关**」——
   `createSynthFx()` **开头就 `if (!options.enabled) return null;`**，连 `output.play` 都不包，
   音频路径上不留任何痕迹。这比「挂上链再把增益调到 0」更干净，也彻底消除了
   「装饰性效果把声音弄哑」这一类风险（原来那套靠闸门保证，现在靠「根本不接线」保证）。
3. **`useSynthFx` 收窄**：`SynthFxController` 只剩 `{ attach, detach }`，
   不再有 `enabled` state / `setEnabled` / `enabledRef`（那三样本来只是为了让用户
   在链路建好之前也能切开关）。
4. **两个 hook 不再透出开关**：`useUkulelePlayer` / `useChordPlayer` 的返回值去掉
   `fxEnabled` / `setFxEnabled`。
5. **`Switch.tsx`** 头部注释更新为「目前只有调音器的自动识别在用」。

**新版验收**：`tsc --noEmit` 与 `npm run build` 通过；三个页面在浏览器里回归——
页面上没有任何开关残留、`src` 里搜不到 `fxEnabled` / `setEnabled` / `音色润色`（只剩注释里
解释「为什么撤掉」的那一处）、效果链照常改接、三种内容都还能出声。
