# ADR 0013: 首页改成一幕场景，靠「位置」破整齐

## 状态

已接受 (2026-09-17)

## 背景

按 ADR 0011，首页叙事区是「站点名 + 副标题 + 一排小猫」，猫由 `layout:'row'` 横排：
容器 `flex`，`.cat { flex: 1 1 0; min-width: 0 }`，四只**等分父容器宽度**，各自 `height: 100%`。

动作那一层其实已经很讲究（12 条准则、踩拍、拖尾、跳跃都有），但用户给的反馈是
**"排列的过于整齐了"**。诊断下来，问题不在动作，在构图 —— 四个变量被同时锁死了：

| 被锁死的量 | 锁死它的是什么 |
|---|---|
| 宽度 | `flex: 1 1 0` 等分 |
| 间距 | 同上，等分即等距 |
| 底线 | `.cat` 全在同一个 flex 行的 `items-end` 上 |
| 尺寸 | 同一个 `--cat-h`，四只一样高 |

于是无论动作多活，**静态的那一帧永远像尺子量出来的**。同时首页还有一处结构性问题：
真正的功能入口是页面下方两张**卡片**，和上面那排猫毫无关系 —— 叙事归叙事、导航归导航。

## 决策

**1. 猫不再是"一排装饰"，而是"待在一个地方"。**

首页顶部改成**一幕场景**（`src/components/scene/HomeScene.tsx`）：一层墙 + 一层木台面，
猫站在台面上，头顶垂着吊灯与挂植，台面右侧一台唱片机。参照用户给的猫咖插画取元素，
**但不照搬造型** —— 猫仍是逐像素描摹稿（几何一字未改），这里换的只是舞台。

景片全部是普通 DOM + `--scene-*` 一组 CSS 令牌（浅色 = 白天咖啡馆；深色 = 打烊后只留一盏灯），
**不引入任何新依赖**。

**2. 入口长在场景上：屋顶垂两块吊牌。**

`SceneSign` 是**真的 `<Link>`**（键盘可达、读屏可识别、右键能新开标签），从场景顶端垂下来、
常驻轻摆、悬停抬牌。原首页那两张入口卡片**删除**。

理由不只是好看：屋顶挂 → 天然有垂直空间；摆动是现成的「跟随与重叠」；悬停抬牌是明确的可点性；
**再加一个入口就多挂一块，布局一行都不用动**。而卡片是"贴在场景边上的按钮"，
和场景本身没有任何关系。

⚠️ 这一条和猫的性质**必须分清**：猫是纯装饰（`aria-hidden`），吊牌是功能入口。
场景里唯一可点、且必须可点的，就是那两块牌。

**3. 「站位」交给 CSS，而且不进 siteConfig。**

新增了 `layout:'scene'`：引擎逐只建盒子，站位**默认一个都不写** ——
只有 `opts.slots` 里显式给了 `x/y/h` 的那几项才写进行内 style（行内优先级最高 = 把控制权从 CSS 收回 TS）。
站点用的是**后者**：位置全部写在 `globals.css` 的 `.home-scene` 一段，PC / 窄屏两套用媒体查询切。

放 CSS 而不是 `siteConfig` 的两个理由：

- **要反复调**。这几个站位是"看着不对就再挪一点"的东西，CSS 能在 DevTools 里实时改，不用等编译；
- ★ **窄屏是重新构图，不是等比缩放**。375px 里塞不下四只猫外加一桌道具，
  必须减到两只、把道具去掉几件、把牌子的位置整个重排 —— 写成配置文件里的数字就切不动了。
  这一点是硬的：窄屏和 PC **不是同一套布局的两种尺寸**，是两套布局。

**4. 唱片机的转速由 bpm 推出来，不是随手定的。**

`secondsPerTurn = 120 / bpm`（默认 96 BPM ⇒ 一圈 1.25 秒，一圈 = 两拍）。
于是唱片每转满一圈，猫正好踩完两下拍子 —— 整幕活在**同一个节拍源**上，
这是"看着像一个东西在动，而不是几段动画各演各的"的来处。改 bpm 时这里要一起改。

## 后果

- ★ **破整齐靠的是位置，不是动作。** 四只猫的 `left`（不等距）/ `bottom`（前后排）/
  `height`（纵深）/ `z-index`（前排压后排）全部不等，**匀了就退回原来那个味**。
  动效引擎一行没为这件事改过。
- ⚠️ **造型宽度 ≈ 框高 × 0.59（站着）/ × 0.79（趴着）** —— 实测出来的。
  也就是说 `height` 每加 10%，身上就多占 6~8% 的画幅宽。**四只一起放大必然打架**，
  这是这套构图最紧的约束（PC 四只合计 71%、窄屏两只合计 72%，都已接近上限）。
  量法：`.home-scene` 与 `svg .norm` 的屏幕矩形相除。
- ⚠️ 引擎的猫层在 scene 布局下必须 `pointer-events: none`（它是 `absolute inset-0`，
  且在 DOM 最后 = 最上面），再由 CSS 把 `.cat` 单独开回 `auto` —— 否则吊牌的点击会被整层盖死。
- ⚠️ `.cat svg` 在 scene 下改成 `width/height:100%`，宽度由 `.cat` 的
  `aspect-ratio: 331.3/351.1`（= `vbThumb`）从高度推出。**换 frame 时这个比例要跟着换。**
- 站点的 `layout:'row'` 与 `frame:'thumb'` 那条路**没有删**：引擎三种布局并存，
  `row` 仍是一姿态一实例的横排实现（对"整齐的一排"这种需求仍然是对的）。
- `siteConfig.cats.height / heightMobile` 现在只有 row 用得上；`cats.enabled` 已无人读
  （首页改由 `scene.enabled` 把门，关掉后曲谱/工具仍有导航栏入口，不会走投无路）。

## 验证（2026-09-17）

- `tsc -b` 干净、`pnpm build` 通过；index chunk 367.4 KB / gzip 128.9 KB
  （改造前 362.6 / 127.2 —— 一整幕场景只多了约 5 KB，全是 DOM 与 CSS）。
- **深浅两个主题各看一遍**：浅色是白天咖啡馆，深色下猫的剪影（引擎 `baseDark` = 纯黑）
  比墨绿墙更深 ⇒ 仍是"黑影 + 亮线"，灯与吊牌是仅有的两处亮色。
  ⚠️ 换色类改动必须两个主题都看过才算验过（`data-col` 那次的教训）。
- **PC / 窄屏各看一遍**（1440×1000 与 390×844）：窄屏确认为另一套构图（两只猫、道具减件、
  牌子重排），不是缩放。
- **可交互性**：吊牌点击实测跳到 `#/tools`；`elementFromPoint` 落在猫身上返回
  `DIV.cat / insideCat=true`（证明 `pointer-events` 的开合是对的，猫没被场景层盖住）。
- 站位是用**屏幕矩形实测**校准的，不是估的；四只猫相邻各留约 1% 重叠（后排被前排压住一点 = 纵深）。
