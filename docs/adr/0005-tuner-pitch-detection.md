# ADR 0005: 调音器采用 Web Audio 自相关检测 + 手动/自动双模式确定目标弦

## 状态

已接受 (2026-09-16)，2026-09-16 补充自动模式（决策 13–17）

## 背景

「工具」页规划了调音器：用设备麦克风判断 GCEA 四根弦的音准。需要在不引入后端、不依赖原曲音频的前提下做出可用的实时测音能力。候选方案：① 时域自相关（ACF）基频检测；② FFT 频谱峰值检测；③ 引入第三方调音库（pitchfinder 等）。

同时，参考的调音器设计里带「自动」开关——自动识别用户弹的是哪根弦。产品上需要决定做到哪一步。

## 决策

1. 用 Web Audio API（getUserMedia + AnalyserNode）取时域波形，自研自相关算法检测基频（`src/lib/pitch.ts`），检测范围限制在 180–1000 Hz。
2. 目标弦由两种**互斥**模式确定，算法层（`useTuner`）只接受一个 `targetFreq`：
   - **手动模式**：用户点选目标弦（C / G / E / A）。
   - **自动模式**（决策 13–17）：由 `useTuner` 内部按实测频率自动挑选。
   检测层不感知模式差异。
3. **默认不预选任何弦**（按钮均不高亮），把「未选弦」当成一等状态：此时读数显示实测音名与该音相对最近十二平均律音高的偏差，让用户一拨弦就有反馈；选弦后切换为相对目标弦的调高/调低指示。
4. 已选弦时，实测频率按八度折叠到目标弦附近（±半音内）后计算音分偏差，保证弹高/低八度时读数仍合理；偏差超过 ±200 音分视为"弹的不是这根弦"，只提示实测音名，不驱动指针。
5. 琴头视觉素材从设计参考截图抠出（`public/images/ukulele-headstock.png`），不额外绘制或生成。
6. 关掉浏览器的回声消除 / 降噪 / 自动增益（echoCancellation、noiseSuppression、autoGainControl 全 false），避免音效处理干扰基频判断。
7. 指示盘用**横向**音分刻度（指针左右移动），缩短垂直占用，保证手机上一屏内完整呈现所有功能区。
8. 分析节点经零增益节点接入 `destination`——部分浏览器不会处理没有下游的音频支路，会导致波形恒为 0、读数永远不出现。
9. 页面内置**信号诊断面板**：实时显示输入设备（可切换）、权限、RMS/峰值、检测频率与置信度、逐帧判定说明与滚动日志。
10. 多帧一致性兜底：单帧置信度 ≥ 0.55 直接采信；否则要求最近 5 帧内频率极差 < 3% 才采信（真实琴弦泛音会让单帧置信度偏低）。
11. 输入设备可切换（`enumerateDevices` + `deviceId: { exact }`），并对虚拟声卡（BlackHole / Soundflower / Loopback 等）给出告警——
    这类设备不采集真实声音，是「拨弦毫无反应」的头号原因。
12. 「跟随系统默认设备」要显式写成 `deviceId: { ideal: "default" }`：已授权后省略 `deviceId` 时，
    浏览器会复用该 origin 上次用过的设备，而不是系统默认（排查中发现用户实际用的一直是 BlackHole，
    而系统默认其实是内置麦克风）。若拿到的 track 命中虚拟设备名且列表里有真实设备，自动切换并重启采集。
13. **自动模式做成一个开关**（`AutoSwitch`，iOS 风格滑块），与手动选弦互斥：打开自动即清空手动选择；在自动模式下手动点某根弦则自动关闭自动、改为手动选中该弦。两种模式都可用时才不显得「二选一很别扭」——用户想锁死校一根就手动点，想扫弦快速过一遍就开自动。
14. 自动识别算法：对每个候选弦把实测频率做八度折叠后算音分偏差，取 |偏差| 最小者；**|偏差| ≤ 100 音分**才认作「像是这根弦」。相邻弦相距 200 音分（G4→A4），±100 正好铺满且不重叠。
15. **防抖**：连续 `AUTO_MATCH_FRAMES = 3` 帧都指向同一根弦才真正切弦；换弦时清空音分平滑窗口（窗口里的中位数是相对旧弦的，必须作废）。锁定前不产生读数，避免扫弦/泛音造成的瞬时误判让指针乱跳。
16. **释放锁定**：听清的音连续 3 帧都贴不上任何候选弦（比如按错了品、或弹了夹在两根弦中间的音）时，释放自动锁定并清空读数，退回未选弦态——不拿旧弦硬比，也不打「不是这根弦」的提示（那会闪一下误导用户）。
17. 自动识别的弦用**呼吸光环**（`.halo-ring`）区分于手动选中的实心按钮；页面文案随模式切换（自动：「弹哪根认哪根」/ 已锁定：「自动识别 · G · 4 弦」）。
18. **逐弦累积「已校准」绿点**：弦钮的绿色不是「此刻正在响且准了」的瞬时状态，而是**保持态**——`TunerPage` 维护 `tunedIds`，当**当前目标弦**（手动选中或自动锁定）判定准了就加入该集合并保持绿色；之后再弹同一根弦明显跑调时移出；停止聆听整轮清零。
    - 视觉区分：**当前正在比对**的那根有光环（准了=绿光环，否则=蓝光环），已校准但不在比对的只有绿底 + 普通投影。不用不同的绿色深浅，避免四种绿难分辨。
19. **信号诊断面板改为「调试模式」门控**，不再是页面常驻内容：`siteConfig.tuner.debug`（默认 false）或地址栏 `?debug=1`。日常界面只保留**虚拟音频设备告警**——它是「拨弦毫无反应」的头号原因，值得在正常界面里说清楚。
20. **响应式版式**（2026-09-16 定稿）：移动端单栏竖排；PC（≥1024px）两栏——左栏「指示盘 + 麦克风开关」（整列撑满、按钮贴底），右栏「琴头与选弦」。
    - 只用**一套 DOM**：左栏容器在移动端 `display: contents`，子元素直接参与外层 flex 排序；`order-1/2/3` 保证移动端顺序是「指示盘 → 琴头 → 麦克风按钮」，PC 上再 `lg:order-none` 重置（⚠️ 忘记重置会让按钮跑到指示盘上面）。
    - 指示盘的音名/刻度/指针用断点等比放大（`--dial-scale` / `--dial-pad` 两个 CSS 变量 + 响应式类），PC 上音名 72px、刻度带 148px、指针 64px。
    - 琴头图宽度按断点给（移动端 `min(146px,37vw)` / sm 170px / PC 184px），PC 上两栏高度差控制在 ~76px 以内。
21. **点弦 / 开自动即自动开麦**：`handlePick(id !== null)` 与 `handleAuto(true)` 里调用 `ensureListening()`（`status` 已是 listening/starting 就跳过，`start` 内部还有一层 `statusRef` 去重）。取消选择（`id === null`）不触发——那属于「我不想校了」，弹权限框只会烦人。麦克风按钮因此退化为「停止」按钮，但仍保留：它是不选弦、纯看实测音名（未选弦态）时的唯一入口。

## 理由

- 自相关对单音弦振动的基频判断比 FFT 峰值更稳，尤其低频段（C4 = 261.63 Hz）在 2048 采样窗下只有约 11 个周期，FFT 分辨率不足。
- 自研约 80 行，无额外依赖，也便于按尤克里里音域调参（门限、置信度、平滑窗口）。
- 手动模式是调音器的常规形态，交互路径最短；默认不选弦既贴合参考设计的「默认无高亮」状态，又通过实测音名反馈避免"拨弦没反应"的困惑。
- 中位数平滑（最近 6 帧）+ 400ms 静音判定，解决读数跳动与"没在弹却显示残影"的问题。
- 横向刻度把指示区从 240px 压到 160px，配合收紧的标题与琴头尺寸，iPhone 14 视口（844px）内无需滚动。
- 识别窗口取 ±100 而非更保守的 ±60：取 60 时弦只要跑偏半个半音就完全认不出来（只能显示「正在识别…」），而调音场景里跑偏 60–100 音分恰恰是最需要被指出的状态。
- 自动识别只做「挑最近的一根」，不引入音高轮廓分析或模板匹配——四根弦频率互不重叠、信噪比高，简单最近邻已足够，也更好debug。
- 绿色必须是**保持态**而非瞬时态：用户实际是「一根根调过去」，靠绿点累积判断进度。若绿色跟读数绑定，琴弦余音一衰减 `reading` 就变 null，绿点跟着消失，等于没有这个反馈（实测复现：手动选 C 弹准音时 C 是绿的，声音一停立刻退回蓝色）。
- 「点弦即开麦」把两步并一步：调音器的真实意图始终是「开始测这根弦」，让用户先点弦再去找开关是多余的心智负担。副作用是首次交互会弹浏览器权限框——这正是需要授权的时刻，比用户点了弦却毫无反应要好。

## 后果

- 用户不选弦时页面仍能给出实测音名的音准反馈，选弦或开自动后切换为「调高/调低」的明确动作提示。
- 麦克风需要 https 或 localhost 环境；页面提供明确的权限失败提示。
- 检测参数（容差、检测范围、平滑窗口）集中在 `siteConfig.tuner` 与 `useTuner` 常量中，便于后续调整；自动识别的三个参数（`AUTO_MATCH_CENTS` / `AUTO_MATCH_FRAMES`）同样在 `useTuner` 顶部常量区。
- 自动模式在**弦跑偏超过一个半音**（>100 音分）时认不出弦，退化显示十二平均律音名——这是有意的：它说明这根弦跑得太远，或是弹了别的音。
- 八度折叠意味着把某根弦弹低整整一个八度（约 1200 音分）仍会被认作该弦且显示「准了」。真实调音场景里不可能出现（弦会松到无法发声），故接受。
- `tunedIds` 只在**当前目标弦**被判定准了时累积。手动模式下不点选就无法知道别的弦的状态，所以「跑调熄灭」只作用于当前比对的弦——这是可接受的：用户本来就要逐根调。
- 诊断面板移出常驻界面后，页面高度回到宽松区间：移动端（390×844）内容约 750px，PC 两栏约 690px，两个视口都一屏内不滚动，琴头素材也从「被视口高掐着 `clamp(...,13.5vh,...)`」改成按断点给定宽度（移动端 `min(146px,37vw)` / sm 170px / PC 184px），视觉上更舒展。
