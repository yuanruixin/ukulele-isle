# ADR 0011: 首页那排小猫 —— 描摹稿 → 骨架数据 → 确定性动效引擎

## 状态

已接受 (2026-09-17)

## 背景

手绘的四只小猫位图已经**逐像素描摹**成 SVG（`docs/preview/traced/*.svg`，几何一字未重画）。
让它们动起来的第一版是「一个文件装下引擎 + 验收页胶水」：`docs/preview/cats-motion.js`（773 行）。
现在要做两件事：

1. 把这排猫放进**首页**（站点名底下的装饰）；
2. 站点与验收页**共用同一个引擎、同一份数据**（改一处两边都跟着变，不再有第二份实现）。

需要定型的取舍：引擎放在哪、数据怎么给到两个壳、页面与引擎各自负责什么、首页怎么开关。

## 决策

- **引擎独立成模块**：`src/lib/catMotion/engine.ts` 导出 `createCatMotion(host, opts) → handle`。
  它**不碰任何 UI**：不注入样式、不读 DOM 尺寸、不认识 React，只认「宿主元素 + 一组姿态」。
  参数合并、实例、共享时钟、渲染全在里面。
- **数据由生成器产出两份同源产物**：`src/data/cats.ts`（**正式消费者读它**，ES 模块 + 类型，
  姿态 id 的联合类型由 ORDER 生成 ⇒ 加一只猫不用手改 TS）与
  `docs/preview/rigged/cats-data.js`（无打包器时的等价副本）。
  源头只有 `.agents/skills/bitmap-to-svg-replica/scripts/build-motion-data.py` 一个脚本，
  两份数据体逐字节相同。
- **站点侧封装成组件**：`src/components/cats/CatMotion.tsx`。它只做三件事——挂载时建一排气囊、
  跟随站点外观换色、卸载时销毁。
- **站点级开关集中到 `siteConfig.cats`**：`enabled` / `poses` / `height` / `heightMobile` / `bpm` / `interactive`。
  「动作怎么演」（阶段时长、跳跃高度、踩拍深度、拖尾量…）留在引擎顶部的 `CAT_CONFIG`，
  两边不互相搬参数。
- **首页把它放在叙事区内部**（副标题之下），是叙事区的一部分，不是第四张卡片。
- **引擎只标事实，页面负责好看**：引擎给盒子挂 `data-pose` / `data-clickable`、把点缀色写在 `.fx` 上的
  `--fx` / `--fx2`；节点样式由壳自己给（站点在 `src/styles/globals.css` 的 `.cat-motion` 一段，
  验收页在它自己的 `<style>` 里）。引擎文件头写明这份 **DOM 契约**。
- **深浅配色是 remap 不是反色**：深色下 base 层换成「猫背后的那个底色」（站点深色下就是 `--bg` 的 #000）⇒
  身体与背景融成一片，只剩一圈亮线；其余层保色相、翻明度（`L' = 0.16 + (1-L)*0.72`）。
- **系统开了「减弱动态效果」就不演、也不接点击**：时间是停住的，这时点一下会僵在预备姿势里，
  不如索性不演（猫照样站在那儿当装饰）。

## 理由

- **为什么引擎不注入样式**：同一个引擎要在两个壳里活（站点组件 / 验收页）。
  样式是壳的事——壳想按高布局、按宽布局、放进卡片还是铺满舞台，都与「动作怎么算」无关。
  把契约写在引擎文件头，比在引擎里塞一堆内联样式更不容易打架。
- **为什么数据走 ES 模块、不做运行时 fetch**：首页首屏就要它，多一次网络往返不如进 bundle
  （代价见「后果」）。验收页从 `/src` 导入 ⇒ 它不能再 `file://` 直接打开，要开着 Vite 看——
  这一页本来就是开发期的验收工具，可以接受。
- **为什么布局是「高度定死 + 四只等分」**：markup 里四只猫已经按**同一个身体高**归一化到同一个舞台
  坐标系（`targetBodyH = 190`），所以给一个高度它们天然是齐的。四只等分父容器宽度 + `min-width: 0`，
  窄屏时不会被内容撑破；被压缩时四只压得一样多，**脚下的地面线始终齐平**（影子、扬尘都在这条线上）。
- **为什么「一个 rAF + 每实例自己的时钟」**：一排猫共用一条 `requestAnimationFrame`，但各自推进自己的
  `t`——既不会 N 个循环抢帧，又能让每块单独暂停/慢放；新挂上来的实例把 `t` 对齐到「已经过去多久」，
  所以一排猫的拍子是同一个乐队的拍子。
- **为什么 `state = f(t)` 必须守住**：动作的每一帧都要能独立算出来，才能支持暂停、慢放、
  把任意时刻**定格**出来逐帧比对间距。任何"接着上一帧继续算"的写法都会让定格失真。

## 后果

- **首屏体积**：index chunk 366 KB / gzip 128 KB，其中约 **39 KB (gzip)** 是猫的数据
  （110 KB 原始 JSON，大头是归一化后的 markup 路径数据）。想还回去有两条路：
  组件改 `React.lazy`（首帧后再下载，猫晚一点出现）或把数据挪到 `public/` 运行时 fetch。
- **一个真实踩过的静默坑**：markup 的根是 `<g class="norm">`（原始坐标 → 舞台坐标的归一化层），
  四个色层在它**底下**。主题换色若照 `svg.children` 取「色层」，只会拿到那一个 `.norm` 组 ——
  于是 `fill` 写在一个没有 `data-col` 的组上、**静默失效**：深色下猫还是白身子，
  与「身体融进背景、只剩亮线」正好相反，而且**不报错**。
  正确做法：色层按 `[data-layer]` 找；`svg.children` 只用来把画面整体搬进 `.rig`。
- 引擎不再有「帧间状态」：新增效果必须能写成闭式，或由**事件时刻**（起跳 / 落地 / 抽动）派生。
- 换色只改 `fill` 属性，几何不动；`paint` 是幂等的，主题来回切不会累积偏差。
- 加第 5 只猫 = 把新的位图描摹成 `docs/preview/traced/<id>.svg`、在生成器的 RIG 表里加一条、重跑脚本，
  `CatPoseId` 会自己长出新的枚举值，首页 `siteConfig.cats.poses` 写错编译期就报。
- 首页要撤掉这排猫：`siteConfig.cats.enabled = false`，页面代码一行不用动。
