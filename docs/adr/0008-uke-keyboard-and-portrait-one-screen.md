# ADR 0008: 虚拟尤克里里的键盘映射、移动端竖置与一屏展示

## 状态

已接受 (2026-09-16)

## 背景

ADR 0007 落地后用户在验收时提了三条追加需求：

1. **点击还要支持映射到键盘**——首版只有「方向键移动光标 + 回车拨弦」，
   那是无障碍式的选择器，不是演奏方式。
2. **为了兼容移动端，应当在移动端竖置**——横放的指板在手机竖屏上只能缩得很小。
3. **保证一屏展示**——整页不滚动（调音器页已有先例）。

动手前先与用户对齐了三处岔路：

| 岔路 | 候选 | 用户选择 |
| --- | --- | --- |
| 键位映射 | 键盘排布式 / 单行选弦+1~4 选弦 / 低把位简化 | **键盘排布式** |
| 竖置方向 | 4 弦在右（顺时针转 90°）/ 4 弦在左 | 4 弦在右 → **后续推翻，见文末「修订」** |
| 一屏范围 | 仅移动端 / PC 也一屏 | **仅移动端** |

## 决策

- **键位 = 键盘排布式**：把键盘的**物理行**对到指板的**弦**上，行内从左到右 = 空弦 0 品 → 高把位。
  - 数字行 = 4 弦 G（13 键 → 到 12 品）、Q 行 = 3 弦 C（12 键 → 11 品）、
    A 行 = 2 弦 E（11 键 → 10 品）、Z 行 = 1 弦 A（10 键 → 9 品）。表在 `src/lib/ukeKeys.ts`。
  - 用 `KeyboardEvent.code`（物理键位），不用 `key`；带修饰键与长按连发都不抢。
  - 监听挂在 **window** 上，进页面直接就能弹，不需要先点一下指板。
  - 首版的「方向键 + 回车」整体删除，只留 Esc 清除高亮。
- **竖置 = 把横放的指板顺时针旋转 90°**（琴枕在上、品位向下、4 弦 G 在右、1 弦 A 在左），
  **不做镜像**——手机横过来就是原来横放的样子。
- **一屏只做移动端**：窄屏整页高度 = `100dvh − 导航栏实测高度`，`overflow-hidden`，
  指板用 `flex-1 min-h-0` 吃掉剩余高度；PC 保持原来宽松、可滚动的版式。

## 理由

- **为什么是键盘排布式**：横放的指板本来就是「弦 → 行、品 → 列」的网格，键盘也是几行键横着排，
  两者的几何是同构的。手指落在哪个键，指板上就响哪一格——**这是找音最快的一种映射**，
  不需要先在脑子里做「选弦 → 选品」两步翻译。备选方案（先按 1/2/3/4 选弦、再用一行键选品）
  虽然每个格子都能按到，但每次换弦都要抬手，弹不成句子。
  代价是真实的：键盘下面两行本来键就少，所以 1 / 2 弦只到 9 / 10 品，这是物理限制，页面图例里明说。
- **为什么必须用 `code`**：`key` 受输入法与键盘布局影响（中文输入法激活时 `key` 可能是拼音候选、
  Dvorak 下物理键位全变），而演奏依赖的是**手指的物理位置**。`code` 正好标的是物理位置。
- **为什么竖置用「旋转整块」而不是「重算几何」**：指板的整套坐标（品丝位置、命中格、拨弦点、
  弦的波形路径）都是「琴枕在左」那一套推导出来的，重算一版竖置几何等于把每个公式写两遍、
  两遍都可能写错。套一层 `<g transform="translate(H 0) rotate(90)">` 之后：
  局部坐标一份、绘图代码一份，连**浏览器的事件命中判定都自动跟着 transform 走**（实测点击有效）。
- **为什么文字要画在旋转组之外**：`<g>` 里的文字会跟着转 90° 躺下，需要就地反向旋转才能立正，
  而那要求「位置用视图坐标、旋转在局部坐标」，两个坐标系混在一个元素上——第一次实现就踩了，
  品位编号全跑到顶上去了。改成在组外直接落视图坐标后，连反向旋转都不需要了。
- **为什么 `rowGapMobile` 从 56 提到 64**：竖置时指板由**剩余高度**等比缩放（`vbH = 几何宽度`
  远大于 `vbW = 几何高度`），缩放比 ≈ 可用高度 ÷ 指板长度，与弦间距无关；弦间距只决定
  「每根弦那一列有多宽」和「整块指板相对有多宽」。调大 → 格子更好按、指板也更铺满屏宽，
  而格子本身的大小不受影响（那由高度决定），所以是纯赚。
- **为什么减掉的导航栏高度要实测**：导航栏是 `h-14`（56px）**再加 0.5px 下描边**，
  实际量出来是 57。差 1px 就会冒出一条滚动条，而 0.5px 这种值不值得写死——
  所以用 `getBoundingClientRect()` 量一次。
- **为什么要去掉格子的焦点环**：格子是 `role="button" tabIndex={-1}`，点一下浏览器会把焦点留在
  那一格上，默认焦点环（蓝色方框）就一直挂着，看起来像「选中了」。键盘弹奏有自己的高亮
  （`cursor` 状态），所以这一格不需要焦点样式，直接 `outline: none`。

## 后果

- **下两行够不到最高几品**（3 弦到 11、2 弦到 10、1 弦到 9）。页面图例里写明了，高把位用鼠标点。
  键位表改动后图例文案会自动跟着变（从 `UKE_KEY_ROWS` + `keyMaxFretOf()` 反推）。
- **竖置时指板尺寸由高度决定**，所以不同机型两侧留白不同；矮屏（如 375×667）上指板会更小。
  想要「永远铺满宽度」需要 JS 量容器尺寸，不值得——现在是高度约束、等比居中，视觉上是稳的。
- **窄屏一屏内**：标题缩到 `text-lg`、指板按剩余高度撑满、录制条切到 `compact`
  （按钮 h-9、序列条 h-9、隐藏说明段）。**序列条出现/消失会改变指板高度**，
  这是 flex 自动重排的结果，不需要额外处理。
- **横竖屏切换会重置按弦状态**（`held` 清空）：切换后指板显示范围与朝向都变了，
  留着旧状态会出现看不见的高把位按弦点。
- 窄屏仍然只显示 7 品（`uke.fretsMobile`）——竖置让每格变大了，但更多品会让指板更长、
  可用高度不变，于是**每一格反而更小**（长度是约束），所以维持 7 品。

## 修订：弦序整体翻转（同日稍后）

验收后用户要求「交换琴弦的顺序」，并明确范围是 **横置 + 竖置都反过来**。原先「竖置 4 弦在右」
的决定被推翻。

**最终弦序**（★ `uke.stringOrder`，默认 `"1-4"`）：

| | 横置（宽屏） | 竖置（手机竖屏） |
| --- | --- | --- |
| `"1-4"` | 上→下 = **1,2,3,4 弦**（1 弦 A 在最上） | 左→右 = **4,3,2,1 弦**（4 弦 G 在最左） |
| `"4-1"` | 上→下 = 4,3,2,1 弦 | 4 弦在右、1 弦在左（= 原方案） |

**一个开关同时管两处，因为它们本来就是一件事**：竖置只是把横置的指板顺时针转 90°，
局部坐标的「上」转到右边，所以「横置的上→下」与「竖置的右→左」是同一串顺序。
翻一次就同时得到「横置 1 弦在最上」与「竖置 4 弦在最左」。

**为什么 `"1-4"` 是对的（而且以前记错了）**：`docs` 与记忆里原先写着「4 弦 G 在上与 TAB 谱
弦序一致」——**这是错的**。查 alphaTab 源码 `TabBarRenderer.getNoteLine(note)`：

```js
getNoteLine(note) { return this.bar.staff.tuning.length - note.string; }
```

行号 0 是**最上面**那根线。而 `Note.string = 弦数` 对应 `\tuning` 的第一根 = 1 弦 A
（本项目 `a4 e4 c4 g4`，1 弦 A 同时也是音最高的那根）。于是 **TAB 最上面那根线就是 1 弦**，
`"1-4"` 才是与 TAB 一致的方向。竖置时它给出的「4 弦在左」也正好是**和弦图**的通行画法
（琴枕在上、弦自左向右 4→1）。

**连带改动（都从弦序派生，不写死）**：

- 几何：`stringRowOrder(弦数, 弦序)` 给出「从局部顶部往下每行放哪根弦」，`boardGeometry`
  只在这一处用它；`boardTop` / `boardBottom` 改用 `min/max(rowY)` 算，不再依赖
  「下标 0 在最下面」（否则翻弦序会把指板底边算到顶上去）。
- 12 品的两个记号点：改用 `boardTop + rowGap*0.75` / `boardBottom − rowGap*0.75` 表达
  （原来是 `rowY[弦数-1] + rowGap/4`，同样写死了下标方向）。
- **键位行 → 弦的绑定**：`keyRowBindings(弦序, 弦数)` 让「键盘最上面那一行」永远对到
  「指板从顶部数第一行」那根弦。翻弦序时手指位置与格子的对应关系不变，不用另改键位表。
  所以现在数字行（13 键，最深）弹 **1 弦 A**，Z 行（10 键）弹 4 弦 G——顺带解决了原先
  「旋律弦只到 9 品」的别扭。
- 页面图例从同一份绑定反推，改弦序文案自动跟着变。

验收：横置 A/E/C/G 的 y = 24/64/104/144（1 弦在最上）、12 品两点仍在指板内；
竖置 G/C/E/A 的 x = 64/128/192/256（4 弦在最左）；键 `1`→1 弦 1 品、`q`→2 弦空弦、
`a`→3 弦空弦、`z`→4 弦空弦；竖屏 `scrollHeight === innerHeight` 仍成立；
击左列得「4 弦 · 第 3 品」、右区得「2 弦 · 第 2 品」，与镜像后的几何一致。
