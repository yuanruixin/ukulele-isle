# ADR 0002: 文件驱动的歌曲注册与配置机制

## 状态

已接受 (2026-09-14)

## 背景

网站需要支持"后期修改配置、添加歌曲"。候选方案：文件驱动（构建时扫描）、public 目录动态读取（免重建）、UI 内编辑后台（需存储层）。

## 决策

采用文件驱动：每首歌一个文件夹（meta.json + score.tex），构建时扫描生成歌曲索引；站点级配置写在项目顶层配置文件中。不引入后端与 UI 编辑后台。

## 理由

- 保持纯静态站，零运维成本，可直接部署到任意静态托管。
- 曲谱与元数据都在 Git 版本管理下，修改可追溯。
- 当前阶段歌曲数量少（从《晴天》前奏起步），构建时扫描的性能与便利性都足够。
- UI 编辑后台需引入存储层（IndexedDB/后端），复杂度与当前规模不匹配。

## 后果

- 添加歌曲需要修改仓库文件并重新构建部署，非技术用户无法自助添加。
- 若未来歌曲量大增或需要用户投稿，需重新评估引入动态加载或后端。
