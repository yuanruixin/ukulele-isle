# ADR 0009: 虚拟尤克里里的音色与输出效果链（换尼龙吉他 + 一条低通混响支路）

## 状态

已接受 (2026-09-16)

> ⚠️ **后续修订（2026-09-17）**：本文里的「**运行时开关**」已经**全部移除**——
> 也就是上面那张**双闸门拓扑图**、决策 2 说明里的「两个闸门是给运行时开关用的」、
> 以及后面「开关放在 `/tools/uke` 头部右上角」那几段。
>
> 演进过程：① 效果链先由 **ADR 0010** 推广到曲谱与和弦库（三个播放器各一条，接线抽进
> `src/hooks/useSynthFx.ts`）；② 随后用户要求「**润色改为本地系统中配置，不需要在页面中添加开关**」，
> 于是三个页面上的 A/B 开关连同 `synthFx.ts` 里的两个闸门、`setEnabled` 一起删掉。
>
> 现在的拓扑是**单路**：
>
> ```
> 合成器输出 → 入口 → 低通×N ┬─ 干声 ────────────┐
>                            └─ 卷积混响 → 湿度 ──┴→ 总增益 → destination
> ```
>
> 有没有这条链**只由各配置块的 `fx.enabled` 决定**：`false` 时 `createSynthFx` 直接返回 null、
> 完全不碰音频路径——比「挂上链再把增益调到 0」干净，也彻底没有「装饰性效果把声音弄哑」的可能。
>
> **其余结论全部仍然有效**：音色号的取证与选择（24 尼龙吉他）、「尖」在 2–6kHz 所以要两级低通、
> 混响归一化的两条坑（`normalize` 顺序、只能用 `reverbMix` 调大小）。

## 背景

用户对照 [musicca 的虚拟尤克里里](https://www.musicca.com/zh/ukulele) 反馈：**本站点指板的声音「有点尖锐」，不如网站好听**。

先做的是取证（不是调参），结论如下——全部来自实测，不是听感推测：

| 项 | 实测结果 | 取证方式 |
| --- | --- | --- |
| 音高 | **是对的**（`a4 e4 c4 g4` → MIDI 69/64/60/67；A 弦 3 品 = C5） | Node + `AlphaTexImporter` 解析 `boardTex()` 的输出，读 `Note.realValue` |
| 音色 | **默认 25 = GM 第 26 号 Acoustic Guitar (steel)，即钢弦吉他** | 同上，读 `track.playbackInfo.program` |
| 力度 | `generateSingleNote()` **把 velocity 写死 95/127** | 逐一把 `beat.dynamics` 设成 pp…ff 再生成 MIDI，events 里一律是 95 |
| 复音 | **单音**：`playOneTimeMidiFile()` 第一步就是 `synthesizer.noteOffAll(true)` | 读 alphaTab 源码（`alphaTab.core.mjs`） |
| 效果 | alphaTab 的合成器**没有任何效果**（API 里搜不到 reverb / chorus / delay / filter） | 检索 `alphaTab.d.ts` |
| 音色库 | `sonivox.sf3` 的 README 自述：移植自三星功能机与 Android 的 SONiVOX EAS、**Frequency 11khz - 32khz**、**no reverb** | 读 `node_modules/@coderline/alphatab/dist/soundfont/README.md` |

也就是说「尖 / 干 / 薄」是四件事叠出来的：**钢弦吉他音色**（尤克里里是尼龙弦）+
**功能机时代的音色库**（采样上限 11–32kHz，且尤克里里的 C4–A5 正好落在吉他音色被往上移调的位置、
共振峰整体抬高）+ **每次拨弦都以固定重力度起音** + **零效果、单音不叠加**。

对照网站的文档（键盘四排 = 四根弦、可标记后整段播放、调音器模式「两个音将同时发声」⇒ 复音）可以确认
它走的是**真实采样 + 效果链 + 复音**这条路；这一点本站短期内不打算跟进（见「后果」）。

## 决策

分两步，都属于「不改发声架构」的范围：

1. **显式指定音色**：新增 ★ `uke.instrument`（默认 **24 = 尼龙吉他**），由 `boardTex()` 写进谱面的
   `\instrument`。alphaTab 不给就用 25 钢弦吉他——钢弦是金属弦，这是「尖」的头号来源。
2. **补一条输出效果链**：新增 ★ `uke.fx`（低通 + 卷积混响 + 干湿比 + 总增益），实现在
   **`src/lib/synthFx.ts`**，挂在合成器**输出节点之后**：

   ```
   合成器输出 → 入口 ┬─ 直通闸 ────────────────────────────────────┐
                     └─ 低通×N ┬─ 干声 ────────────┐               │
                               └─ 卷积混响 → 湿度 ──┴→ 总增益 → 效果闸 ┴→ destination
   ```

   两个闸门是给「运行时开关」用的：开 = 效果闸放行，关 = 直通闸放行（增益恰好 1，
   等于 alphaTab 的原始直出）。混响的脉冲响应是**程序生成的衰减噪声**（先过一阶低通抹暗、
   前 25ms 留空当预延迟），不需要额外音频素材。

> 另外两件事**明确不做**（成本与收益不成比例，见「后果」）：复音叠加、把力度从写死的 95 里解放出来。

## 理由

- **为什么不是「换个音色库」**：那是天花板更高的做法（全站受益，曲谱播放也会一起变好），
  但要挑库、包体会显著变大，而且换库之后仍然没有混响——先做这两步，把「尖」和「干」按住，
  换库留作后续独立决策。
- **为什么 `\instrument` 必须写在那个位置**：alphaTex 里它要落在「进入 track 之后、`\tuning` 之前」
  才生效（放在 `\tempo` 之前、或放在小节之间都不行），已在 1.8.4 上逐个位置试过。
- **为什么效果链要包住 `play()` 而不是只接一次线**：alphaTab 的播放节点藏在输出对象的私有字段里
  ——`_worklet`（AudioWorklet 模式，默认）或 `_audioNode`（ScriptProcessor 回退）——并且
  **每次 `play()` 都会重新 new 一个**、AudioWorklet 那条路还是**异步**建的（`.then()` 里才赋值 + connect）。
  所以只能包住输出实例的 `play()`（**改实例不改正型**，只影响这一个播放器），每次接一次线，
  并允许「这次还没建好、过一会儿再试」。
- **为什么能用私有字段**：`alphaTab.api.player.output` 是公开 getter，且 worker 模式下返回的是
  **主线程**那个输出对象（worker 只负责渲染采样、通过 `alphaSynth.output.play` 消息让主线程播）。
  两个字段名任一个拿不到就**什么都不做**——装饰性效果绝不能把声音弄哑。

## 后果

- **`synthFx.ts` 依赖 alphaTab 的私有字段名**（`_worklet` / `_audioNode`）。升级 alphaTab 时要回看这两处；
  失效的表现是「声音照旧、只是没有效果」，而且控制台会留下 `[synthFx] 始终没找到 alphaTab 的播放节点`。
- **只挂在虚拟尤克里里这一个播放器实例上**，不做全局改造。和弦库与曲谱页各有自己的播放器实例，
  目前**没有**这条效果链（同样的「干」问题在那里依然存在）。
- **仍然没有解决的问题**（想要更接近网站就得离开 alphaTab 的发声）：单音不叠加、
  力度固定 95 无法调节、音色库本身只有 11–32kHz。
  彻底对齐网站的做法是**自己用 Web Audio 播真实尤克里里采样**，但那要引入采样素材并重写发声层。
- 效果参数已从「听感默认值」换成**实测值**：低通 **两级 3400Hz**（巴特沃斯 Q）、湿度 **0.25**、
  1.2 秒、总增益 0.9。页面右上角有开关可以随时 A/B（见下面的修订）。
- 验证方式（无头也行，三件套，按可信度从高到低）：
  1. **并联支路频谱扫描**（最可信，完全自包含）：建一组只差参数的滤波器支路（都接到同一个
     正弦组 + 一个参考分析器），一次读出就能得到「截止 × 级数 → 各频点衰减」的对照表，
     不受链路状态与相位影响。
  2. **逐节点电平图**：给链路上每个节点各挂一个 AnalyserNode，同时读同一频率的电平，
     一眼看出「闸门是否真在开合、湿声比干声低多少 dB」（⚠️ 单频读数自带约 ±5–10dB 的种子抖动，
     只看趋势、别抠小数，理由见修订第 3 条）。
  3. 钩 `AudioNode.prototype.connect/disconnect` 看改接是否发生。
  ⚠️ **给节点编号再认人**：探针必须自己给每个 AudioNode 发唯一 ID（WeakMap）并按**连接关系**
  推角色；按「第几个被创建的 GainNode」这种数组下标认节点会被自己新建的节点（分析器 sink、
  测试信号）挤偏，曾经因此得出过一堆互相矛盾的数字。

## 修订（2026-09-16 深夜）：第一版为什么「开了像没开」

用户反馈「**开启前后毫无变化，感觉没有润色**」。重新取证后确认：**开关本身一直是好的，
是效果弱到听不出来**，原因有两个，都是量出来的：

1. **低通开错了地方**。第一版是单级 4200Hz——6kHz 只掉约 5dB，而「刺」恰恰在 2–6kHz。
   等于滤波器躲开了它该管的频段。现在改成**两级 3400Hz**（巴特沃斯 Q）：6kHz −21dB、10kHz −44dB，
   通带内仍然平直。下面是滤波器自身的频响（解析值，浏览器实测相差 2dB 以内）：

   | 截止 | 级数 | 1k | 2k | 3k | 6k | 10k |
   |---|---|---|---|---|---|---|
   | 2400 | 2 | 0.0 | −0.9 | −8.6 | −33.7 | −55.9 |
   | **3400** | **2** | 0.0 | −0.1 | −1.3 | **−21.3** | −43.5 |
   | 4400 | 2 | 0.0 | 0.0 | −0.2 | −12.1 | −34.1 |
   | 3400 | 1 | 0.0 | −0.5 | −2.0 | −11.0 | −21.8 |

2. **混响的湿度是错的量级**。ConvolverNode 默认 `normalize = true`，会在赋 buffer 那一刻
   按自己的算法把手写的噪声 IR 又放大一截，于是 `reverbMix: 0.2` 出来的湿声有干声的 0.63 倍、
   低中频被垒起 +6dB——听感是「糊、变响」，不是「有空间」。修法是**在赋 `buffer` 之前**设
   `normalize = false`（写在之后不生效，实测差到 13 倍）。关掉之后卷积就是严格的「输入 ⊛ IR」，
   湿/干电平比 = `reverbMix`：**0.25 → −12dB**（= 20log₁₀0.25；实测 0.12 → −18.4dB 与之吻合到 0.1dB）。
   所以**混响大小只能靠 `reverbMix` 调**，缩放 IR 是白费力气。
3. ⚠️ **别拿单一频率去量「湿声低了多少 dB」**——这是本案最后一个坑，也是文档里一度出现
   三个互相矛盾的 dB 数字的原因。我们的 IR 是暗噪声，|H(f)| 在 0.6–2.0 之间起伏（低频厚、高频薄），
   而且换个随机种子同一频点还能再差 5–10dB（单频点服从瑞利分布）。要量就取一段频带
   （1/3 倍频程以上）的能量平均，或者干脆用宽带噪声当测试信号。
   顺带：低通后面挂着混响支路，所以「整条链」的读数会在 1–3kHz 鼓出约 +3dB——要量低通本身，
   请量**低通输出**那个节点，别量总输出。

同时补上：**运行时开关**（`SynthFxHandle.setEnabled`）——只动链内「直通闸 / 效果闸」两个增益、
带 15ms 交叉淡化，**不重建 alphaTab、不打断正在响的音**，所以能按住一个音反复 A/B；
开关放在 `/tools/uke` 头部右上角（绝对定位，不占高度——窄屏是一屏布局，多 1px 就冒滚动条），
初值取 `uke.fx.enabled`，该选择不持久化。

顺带修掉两处：低通 Q 全部取同一个值会在 3kHz 拱出一个包（鼻音），改为巴特沃斯那组 Q；
混响 IR 的预延迟从 10ms 提到 25ms，让音头与早期反射分开、少一点梳状毛刺。
